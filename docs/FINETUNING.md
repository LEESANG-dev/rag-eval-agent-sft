# SLM 파인튜닝 실험 — Qwen3-8B LoRA (규정 QA 특화)

35B로 서비스하는 규정 QA를 **8B가 얼마나 대체할 수 있는지**, 그리고 측정으로 확인한 약점(표 오독)을 **파인튜닝으로 보완할 수 있는지** 확인한 실험 기록입니다.

> 실행 스크립트는 [`sft/`](../sft/) 에 있습니다.
> 전제가 되는 검색 파이프라인·평가 체계는 [ARCHITECTURE.md](ARCHITECTURE.md) 참조.

---

## 1. 실험 구성

| 역할 | 모델 | 위치 |
|---|---|---|
| 선생 (데이터 생성·채점) | qwen3.6-35B-A3B | 운영 GPU 서버 (vLLM, 서비스 중인 API 그대로 사용) |
| **학생 (튜닝 대상)** | **Qwen3-8B** | RTX PRO 5000 Blackwell 48GB (유휴 장비, 폐쇄망) |

폐쇄망 제약으로 모델 가중치(16.4GB)와 의존성은 인터넷 연결 PC를 스테이징 삼아 물리 반입했습니다. 의존성 반입을 최소화하기 위해 **trl/datasets 없이 transformers Trainer + peft만** 사용했고(추가 휠 1개), 학습은 기존 vLLM cu129 컨테이너(torch 2.11, sm_120) 안에서 실행했습니다.

## 2. 학습 데이터 — 35B 증류 + 3중 필터

[sft/gen_train_data.py](../sft/gen_train_data.py) — 평가셋 생성기의 검증된 필터를 재사용하되, 학습용으로 강화했습니다.

| 필터 | 목적 |
|---|---|
| **근거불일치** | 정답의 모든 수치가 원문에 실제로 존재해야 함 — **선생의 환각이 학습에 들어가는 것을 차단** |
| **평가셋 중복** | 394건 평가 질문과 3-gram 유사도 55% 이상이면 폐기 — **시험 문제 유출 방지** |
| 형식 | 순번 암기형·문서 지시형·부정형·길이 미달 폐기 |

**샘플 형식** — 실서비스 RAG와 동일한 (검색 결과 + 질문 → 근거 인용 답변) chat 구조. 8B가 배우는 것은 규정 암기가 아니라 **"주어진 컨텍스트를 정확히 읽고 답하기"** 입니다. 측정에서 확인된 약점을 겨냥해, B유형 프롬프트에 *"표의 행과 열을 교차 참조해야 답할 수 있는 질문 우선"* 조건을 명시했습니다.

**결과**: train 2,444 / val 109 (문서 단위 분리). 유형 구성 A 1,200 / B 549 / C 600 / D 200 — B는 근거불일치 필터의 높은 폐기율로 소스가 소진되어 목표(1,200) 미달.

## 3. 학습

[sft/train_lora.py](../sft/train_lora.py)

| 항목 | 값 |
|---|---|
| 방식 | bf16 LoRA (r=16, α=32, dropout 0.05) — bitsandbytes 없이 48GB에 적재 가능해 양자화 리스크 회피 |
| 타겟 | attention + MLP 전 레이어 (학습 파라미터 43.6M = 0.53%) |
| 손실 | **assistant 응답 토큰만** (프롬프트 -100 마스킹) |
| 배치/lr | 유효 배치 16 (1×accum16), lr 1e-4 cosine, 2 epoch |
| 시퀀스 | max 4,096 (초과 373건 제외 → 실사용 2,071건) |
| 결과 | train loss 0.28→0.16, **val loss 0.213 (ppl 1.24)**, 1.9→2.0ep 사이 정체 — 과적합 없음 |
| 소요 | 60분 (GPU 99%, 피크 40.6GB) |

시행착오 기록: transformers 5.12의 `apply_chat_template`이 `BatchEncoding(UserDict)`을 반환해 구버전 코드가 죽는 문제를 스모크 테스트에서 발견 — 반환형 4종(list/str/Encoding/BatchEncoding)을 흡수하는 헬퍼로 해결. **8B라 로드가 6초여서 이런 시행착오가 즉시 드러났습니다.** 35B로 바로 갔다면 시도당 수십 분을 냈을 비용입니다.

## 4. 평가 — 3자 비교

**프로토콜**: 평가셋 394건의 질문 + **gold context**(정답 근거 문서 원문)를 세 모델에 동일하게 제공, temperature 0, 35B가 채점. 답변 생성은 학습에 쓴 GPU 서버에서 vLLM으로 base와 LoRA 어댑터를 **동시 서빙**(`--enable-lora`)해 각 85초에 완료.

| 모델 | 전체 | A 규정본문 | B 별표 | C 연계 | D 공지 |
|---|---:|---:|---:|---:|---:|
| base 8B | 92.4% | 96.4% | 90.0% | 86.5% | 97.5% |
| **LoRA 8B** | **93.4%** | 93.6% | **92.9%** | **90.5%** | **100%** |
| 35B (선생) | 95.7% | 98.6% | 93.6% | 91.9% | 100% |

### 플립 분석 — 어디서 오르고 어디서 내렸나

| 방향 | 건수 | 유형 분포 |
|---|---:|---|
| 개선 (0→1) | 13 | **B 6, C 4**, A 2, D 1 |
| 악화 (1→0) | 9 | **A 6**, B 2, C 1 |

**개선은 정확히 겨냥한 곳(B 표 독해, C 연계)에 집중**됐습니다. B는 선생과 0.7%p 차이까지 근접했습니다.

**A의 후퇴는 원인이 분명합니다.** 악화 샘플을 보면 수치는 맞는데 **다항목 질문에서 일부 항목을 누락**합니다 — "예외 4가지" 중 1가지만 답하는 식. 증류 데이터의 답변이 짧은 편이라(평균 ~40자), 모델이 **간결함을 학습하면서 완전성을 잃었습니다.** 학습 데이터의 문체가 모델 행동을 그대로 조형한다는 직접 증거입니다.

### 해석의 한계 (명시)

- 전체 +1.0%p는 394건 중 4건 차이 — **단독으로는 통계적 유의성을 주장하기 어려움**. 다만 개선의 유형 분포가 설계 의도와 일치하는 것이 우연일 확률은 낮음
- gold context 제공 시험이라 base가 이미 92.4% — **천장 효과**. 실전(검색 포함) 격차는 더 클 수 있음
- 35B가 자기 답변도 채점 — **자기편향 가능성**

## 5. 실전 E2E 검증 — 결론이 뒤집히다

gold context 평가는 튜닝 모델의 우세(+1.0%p)를 보였지만, **배포 조건은 다릅니다.** 실제 서비스에서 모델은 컨텍스트를 받는 게 아니라 **스스로 검색 도구를 호출**해야 합니다. 8B를 터널로 운영 파이프라인에 연결해(검색·도구·문서는 실서비스 그대로) 동일 E2E 프로토콜로 재평가했습니다.

### 결과 — gold context와 정반대

| 모델 | gold context | **실전 E2E** |
|---|---:|---:|
| 35B (현행) | 95.7% | 88.6% |
| base 8B | 92.4% | 81.5% |
| **LoRA 8B** | **93.4%** (base+1.0) | **67.3%** (base−14.2) ⚠️ |

**gold context 평가만 믿고 배포했다면 서비스 정확도가 88.6% → 67.3%로 추락했을 것입니다.**

### 원인 분석

| 지표 | base | LoRA |
|---|---:|---:|
| 도구 미호출 | 7건 | **77건 (19.5%)** |
| 그중 정답 | 0 | 13 |

두 가지가 확인됐습니다.

1. **도구 호출 습관 상실** — 학습 데이터가 전부 "컨텍스트 제공 → 즉답" 형식이라, 컨텍스트가 없으면 검색부터 해야 한다는 행동이 지워졌습니다. 시스템 프롬프트와 도구 설명에 *"반드시 도구를 먼저 호출하라"* 는 명시적 지시가 있었음에도 77번 무시했습니다(base는 7번). **가중치에 새겨진 습관이 프롬프트 지시를 이깁니다.**
2. **어설픈 암기의 환각** — 검색 없이 답할 때 학습 중 본 규정을 비슷하게, 틀리게 재현합니다. (예: 명예퇴직 근속요건 20년 → "10년"으로 답변) 부분 암기가 실전에서 그럴듯한 오답으로 발현된 것입니다.

### 반증 실험 — 원인 격리

프롬프트 지시는 이미 실패했으므로, **API 레벨 강제**(`tool_choice="required"`, 첫 턴 한정)로 도구 호출을 물리적으로 보장하고 재평가했습니다.

| | 도구 자율 | **도구 강제** | 변화 |
|---|---:|---:|---:|
| base 8B | 81.5% | 82.7% | +1.2%p |
| **LoRA 8B** | 67.3% | **82.7%** | **+15.4%p** |

첫 턴 강제만으로 LoRA가 base와 **정확히 동률로 회복**됐습니다(도구 미사용 0건). base는 거의 움직이지 않아 강제 모드 자체의 효과가 아님도 분리 확인됩니다. **독해 능력은 손상되지 않았고, 무너진 것은 도구 호출 행동뿐**이라는 가설이 확정됐습니다.

강제 모드에서도 튜닝의 흔적은 유형별로 남습니다 — C 연계 +2.7%p, D 공지 +7.5%p (겨냥한 개선), A −2.8%p (완전성 부작용). 전체로는 상쇄되어 **실전 순이득 0**입니다.

1차의 결론: **실전 실익 0.** 그러나 원인이 격리됐으므로 다음 반복의 요건이 정확히 규정됐습니다 — *증류 시 도구 호출 궤적을 포함할 것.* 이를 2차에서 실행했습니다.

## 6. 2차 — 에이전트 궤적 증류 (요건 반영)

### 데이터: 35B가 실제로 일하는 과정을 녹화

1차 질문 2,444개를 35B 에이전트에 다시 넣어, **전체 궤적**(질문 → `semantic_search` 호출 → 도구 결과 → 답변)을 녹화했습니다 ([sft/gen_agent_traces.py](../sft/gen_agent_traces.py)).

| 필터 | 목적 |
|---|---|
| judge 검증 (탈락 184) | 35B의 답이 검증된 정답과 일치하는 **성공한 행동만** 증류 |
| 즉답 궤적 폐기 (32) | 도구 없이 답한 궤적 차단 — 나쁜 습관 재유입 방지 |
| 턴 초과·오류 제외 (87) | 실패 궤적 배제 |

**채택 2,141건** (도구 호출 1회 1,948 / 2회 157 / 3회 36). 학습은 다중 턴 마스킹 — **assistant 턴(도구 호출 결정 + 최종 답변)에만 손실**을 걸고 system·user·tool 턴은 제외했습니다. 도구 출력을 흉내내도록 배우면 안 되기 때문입니다. val loss 0.1668 (1차 0.213), 2시간 7분.

### 템플릿 정렬 버그 2건 — 같은 뿌리에서

Qwen3 채팅 템플릿은 **마지막 assistant 턴에만 빈 `<think>` 블록을 붙입니다.** 이 비대칭이 학습과 서빙에서 각각 한 번씩 사고를 냈습니다.

**버그 ① 마스킹 누수 (학습 전 발견)** — 누적 렌더 길이로 손실 경계를 잡자 도구 호출 턴의 스팬이 다음 턴 헤더로 새어 들어갔습니다. 방치했으면 모델이 도구 호출 뒤 `<|im_start|>user`를 생성하도록 배웠을 것입니다. 토큰열에서 assistant 블록을 직접 스캔하는 방식으로 교체하고, **학습 전 마스킹된 스팬을 디코드해 육안 검증**하는 절차를 추가했습니다.

**버그 ② think 프리필 (평가에서 발견)** — 첫 평가가 **17.8%로 붕괴**했고 도구 사용이 7/394였습니다. 궤적으로 학습한 모델에서 나올 수 없는 행동이라 프로브 실험을 했습니다.

```
같은 모델, 같은 질문:
  enable_thinking=False (빈 think 프리필)  → 즉답 + 환각 ("일비 100,000원")
  프리필 제거                              → semantic_search 정상 호출
```

학습 데이터에서 빈 think 블록 뒤에는 **예외 없이 최종 답변**이 왔습니다(도구 호출 턴에는 템플릿이 think를 붙이지 않으므로). 평가 설정이 모든 생성 앞에 그 블록을 프리필하자, 모델은 매번 "답변할 차례"로 판단해 도구를 건너뛴 것입니다. 프리필을 제거하니 정상 동작했습니다.

> **교훈** — 학습 시 렌더링과 서빙 시 렌더링은 **토큰 단위로 일치**해야 한다. 템플릿의 사소한 비대칭이 행동을 통째로 뒤집는다.

### 최종 결과 — 자율 모드에서 습관 복원

| 모델 | 도구 자율 | 도구 강제 | 도구 사용률 |
|---|---:|---:|---:|
| 1차 SFT (즉답 데이터) | 67.3% | 82.7% | 317/394 |
| base 8B | 81.5% | 82.7% | 387/394 |
| **2차 SFT (궤적 데이터)** | **83.5%** | (불필요) | **394/394** |
| 35B (현행) | 88.6% | — | 391/394 |

- **도구 미호출 77건 → 0건.** 아무 강제 없이 394건 전부 검색부터 수행 — **행동이 데이터로 복원**됐습니다.
- 자율 모드 83.5%는 base(+2.0%p)는 물론 **강제 모드 상한(82.7%)도 넘습니다.** API 강제는 응급처치였고, 데이터가 근본 해법이었음이 확인됩니다.
- **점수 이득의 유의성은 약합니다** — 플립 28(개선) 대 20(악화), p≈0.25로 단독으로는 우연을 배제할 수 없습니다. 확정적인 것은 범주형 행동 지표(도구 미사용 77→0건, base의 도구 미사용 실패 7건 중 5건 회수)이며, 점수는 "base 동등 이상"이 정확한 표현입니다.
- 유형별: A 97.1% / C 83.8% (모든 8B 구성 중 최고). 단 **B 별표는 76.4%로 base보다 낮아** 1차 gold context의 표 독해 이득이 실전으로 이어지지 않았고, D 공지(60.0%)도 여전히 최하위입니다.

## 7. 결론

**확정된 사실들**

1. **행동은 데이터로 가르친다** — 즉답 데이터는 도구 습관을 지웠고(67.3%), 궤적 데이터는 복원했다(83.5%). 프롬프트 지시(무력) < API 강제(응급처치, 82.7%) < **학습 데이터(근본, 83.5%)** 순으로 강하다.
2. **평가 프로토콜은 배포 조건과 일치해야 한다** — gold context(+1.0%p)와 실전 E2E(−14.2%p)는 정반대 결론을 냈다.
3. **학습·서빙 렌더링은 토큰 단위로 일치해야 한다** — 템플릿 비대칭 하나가 마스킹 누수와 17.8% 붕괴를 각각 일으켰다.
4. **35B 유지** — 최선의 8B(83.5%)도 35B(88.6%)와 5.1%p 차이. 품질 기준으로 교체 근거 없음. 격차가 ~2%p로 좁혀질 때 처리량(GPU 4장→1장)과의 교환을 재검토한다.

**남은 과제** — B 별표 실전 독해(76.4%), D 공지(60.0%), 다항목 완전성. 표 특화 데이터를 궤적 형식으로 재증류하는 것이 다음 후보입니다.
